# CeeVeeGlobal (CVG)

## What it is (elevator pitch)
ceeveeglobal.com is a WordPress tutorial site whose posts are produced by a
scripted content pipeline — Python scripts calling Claude, drafts staged for
review in a local Flask dashboard, then published to the live site. Since
August 2026 it also sells: `/web-design` is a "Web Factory" offer — AI-built
websites for small businesses, with clients kept on ongoing Care Plans.

## Current status
Live and publishing. Three things changed in the last two months: the whole
project moved off a laptop onto an always-on home server (2026-08-06), the
`/web-design` sales page and lead-capture funnel launched (2026-08-10), and a
runaway-backup problem that would have filled the VPS disk was cleared
(2026-09-02). A second site, ABT, shares the same VPS.

## Key numbers
- 98 published posts (2026-09)
- VPS disk at 63 GB of 193 GB — 33%, 130 GB free — after the backup cleanup;
  it was 76% and climbing ~1 GB/day before (2026-09)
- 35 containers on the VPS; WordPress uploads for CVG are 717 MB (2026-09)
- Backups now self-prune to 7 daily sets, ~9 GB steady state (2026-09)

## Architecture / how it works
WordPress on a Coolify-managed VPS, sharing the box with ABT, n8n, Mautic and
MinIO. The pipeline itself runs on `dim-OptiPlex-7060`, a Dell OptiPlex 7060
running Ubuntu at home: the Flask review dashboard is a systemd service
reachable on the LAN, the Error Library pipeline publishes on a daily systemd
timer (04:00), and the project is swept 4-hourly to Google Drive by rclone.
Front-end work ships as WPCode PHP snippets installed by scripts rather than
as theme edits. Images are never generated by code — see
[[fact-2026-07-no-image-generation-apis]].

Pinterest is a half-built third channel: local pin generation, MinIO upload
and a MongoDB `pins_queue` handoff are built and tested; the n8n publishing
side is deliberately deferred, and the Pinterest API app ("CVG Pin
Automation") was still pending Trial approval as of 2026-07.

## Decisions & constraints
- No script may call an image-generation API, anywhere in the pipeline. Dimu
  generates images by hand from written prompts.
- The pipeline is Optiplex-hosted only. Per Dimu's explicit instruction,
  nothing is wired into Coolify beyond reaching the two live WordPress sites;
  an SSH key added from the Optiplex to the VPS was deleted the same day.
- The Error Library pipeline auto-publishes live with no review gate
  (`ERROR_PIPELINE_PUBLISH_STATUS=publish`).

## Open risks / follow-ups (flagged 2026-09-02, not blocking)
- Backups are local-only — no remote target configured, so a disk failure
  loses the site and its backups together. Pointing them at the existing
  MinIO/S3 bucket is the obvious fix.
- Swap is 3.8 GB of 4.0 GB used: six separate `mysqld` instances on an 11 GB
  box, CVG's alone swapping ~960 MB, load 4–7 on 6 cores. A memory problem,
  untouched by the disk cleanup.
- Zoho SMTP is rejecting `wp_mail()` site-wide ("Unusual sending activity
  detected"), so quote-request notification emails don't arrive. Leads are
  still captured in the database.
- The primary nav menu isn't assigned to a menu location, so a "Web Design"
  header link can't appear until that's fixed.
